# Phase 5 — Executive Dashboard, Management Reports, Excel/PDF Exports, Security Validation

## 1. Changes

No new business tables. Phase 5 adds:

| Item | Purpose |
|---|---|
| Report engine (`server/modules/reports.ts`) | A catalogue of the 14 management reports. Each report declares its columns, the permission(s) needed, the date its date-range filter applies to, and which common filters it supports. One query builder applies the filters safely (parameterised SQL only). |
| Exports | **Excel** (`.xlsx`): title, company, filters applied, generated by / at, frozen header row, auto-filter, number formats, totals row. **PDF** (A4 landscape): same header, repeating column headings, page numbers, totals row, automatic column sizing and text wrapping. |
| Backups | Automatic daily backup inside the server (default 02:00 Gulf Standard Time, keeps the last 30) for the embedded database, plus uploaded documents. Administrators can see the backup list and start one on demand. With an external PostgreSQL server, `pg_dump` is used where available. |
| Security validation | An automated security test suite and `docs/SECURITY.md` summarising controls and results. |

## 3. Executive dashboard
The dashboard (Phases 1–4) is completed with a **"CEO questions" panel** that answers the 14 questions in the specification in one place — selected, expected to arrive, confirmed tickets, arriving today/tomorrow, awaiting pickup, with accommodation, awaiting medical, visa pending, training not completed, uniform/PPE not received, delayed activities, spend per employee, ready for deployment, deployed — each linking to the detailed list or report.

## 4. Security validation (automated)
* Every API route rejects unauthenticated access (enumerated from the router, not a hand-written list).
* Role isolation: each role is refused the endpoints outside its permissions (sample per module), and documents/salary/costs are hidden from roles without access.
* Injection: SQL meta-characters in search, sort, filter and report parameters are treated as data.
* CSRF: cross-origin state-changing requests are rejected; session cookie is `HttpOnly` + `SameSite=Strict` (+ `Secure` in production).
* Brute force: account lock-out and login rate limiting.
* Uploads: content-type sniffing (disguised executables refused), size limit, no path traversal in stored names.
* Headers: Content-Security-Policy, `X-Content-Type-Options`, no `X-Powered-By`, frame protection.
* Error handling: internal errors never leak stack traces or SQL to the client.
* Passwords: bcrypt hashing, strength policy, forced change of temporary passwords, sessions revoked on password reset / deactivation.
